# Super RClick Release Build And Install

## Build

Run the repeatable release packaging script:

```bash
./scripts/build_release_dmg.sh
```

What it does:
- Regenerates the Xcode project from `project.yml`
- Builds `SuperRClick.app` in `Release`
- Verifies the Finder Sync extension is embedded in the app bundle
- Stages the app and creates a compressed DMG in `output/release`

## Minimum macOS Version

The deployment target is **macOS 15.0** for the app, Finder Sync extension, and shared framework. Both deployment settings in `project.yml` must stay aligned. After changing them, run `xcodegen generate` and rebuild; editing only an app's `Info.plist` does not change the minimum OS encoded in its executable.

The app and extension source plists inherit `LSMinimumSystemVersion` from `$(MACOSX_DEPLOYMENT_TARGET)`. The shared framework's plist is generated by Xcode. A newer SDK is acceptable as long as newer APIs are guarded and all targets retain the supported deployment target.

Before distributing a build, verify the staged app:

```bash
./scripts/verify_compatibility.sh "output/release/staging/SuperRClick.app"
```

The verifier checks `LSMinimumSystemVersion` and the Mach-O minimum version for every architecture present in the app, embedded Finder Sync extension, and shared framework. It also accepts a directly built `.app` path, so a Debug build can be checked without creating a DMG. A universal release should contain both `arm64` and `x86_64`; the verifier prints the architectures it inspected but does not require both in a local Debug build.

The earlier local v0.2.1 staging bundle declared macOS 26.0 in its plist and both executable slices, despite the README stating macOS 15+. Lowering the deployment target corrects that build configuration mismatch. It does not update previously published downloads.

Successful compilation and bundle checks establish API availability and packaging metadata only. **Runtime behavior on macOS 15, including 15.6.1 from [issue #2](https://github.com/CalvinQin/SuperRClick/issues/2), still requires validation on that system.** Before claiming the release is verified there, test:

1. Launch the packaged app on macOS 15 and open each sidebar page.
2. Enable the Finder extension and use its menu on a disposable folder and file.
3. Create a file, copy a path, preview/cancel a batch rename, and apply a rename to disposable files.
4. Save and reopen preferences; quit and relaunch the app.
5. Record the exact macOS version and processor architecture tested. Test Intel separately before claiming Intel runtime coverage.

## Output

Expected output:
- `output/release/SuperRClick-<version>.dmg`
- `output/release/staging/INSTALL.txt`

## Install

1. Open the DMG.
2. Drag `SuperRClick.app` into `Applications`.
3. Launch the app once.
4. If the Finder extension is not active yet, use **Open Extension Settings** in the app's setup guide. The button opens macOS's native extension management interface. On macOS 15–27, the manual path is `System Settings -> General -> Login Items & Extensions`; enable the Super RClick Finder extension there.
5. If Finder still shows no Super RClick menu, relaunch Finder once.

## Notes

- The app reads extension enablement using [`FIFinderSyncController.isExtensionEnabled`](https://developer.apple.com/documentation/findersync/fifindersynccontroller/isextensionenabled) and opens settings using [`showExtensionManagementInterface()`](https://developer.apple.com/documentation/findersync/fifindersynccontroller/showextensionmanagementinterface()). Both APIs support macOS 10.14 and later. It rechecks Finder, Accessibility, and Input Monitoring status when the app becomes active; an enabled extension still needs a real Finder-menu check.
- Apple's [Login Items & Extensions guide](https://support.apple.com/guide/mac-help/change-login-items-extensions-settings-mtusr003/mac) documents the current settings path. The optional desktop enhancement needs separate Accessibility and Input Monitoring permissions; the app only requests those after the user selects the corresponding setup button.
- Debug sessions using an absolute `SUPERRCLICK_TEST_STORAGE` path skip native extension checks, activation observers, permission checks in the setup guide, and system-settings actions. They do not establish real Finder integration or permission coverage.
- The current release script now applies local ad-hoc bundle signing to the staged app and embedded Finder Sync extension so `pluginkit` can register the extension on a development machine.
- The DMG already contains the app bundle with `SuperRClickFinderSync.appex` embedded.
- A polished icon source is kept separately so the icon worker can convert it into `AppIcon` assets without touching packaging logic.

## Troubleshooting

If the right-click menu does not appear:

1. Confirm Finder sees the extension:

```bash
pluginkit -m -A -D -p com.apple.FinderSync | grep SuperRClick
```

2. If nothing is listed, register the installed extension manually:

```bash
pluginkit -a "/Applications/SuperRClick.app/Contents/PlugIns/SuperRClickFinderSync.appex"
pluginkit -e use -p com.apple.FinderSync -i com.haoqiqin.SuperRClick.FinderSync
```

3. Restart Finder:

```bash
killall Finder
```
